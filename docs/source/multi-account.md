# Multi-account attribution

The multi-account module adds three **separate** calculations without changing the existing single-account Brinson functions. They answer different decision questions. All require positions with a unique `(period, account, sector, security)` key and beginning-of-period portfolio market value $V^P_{ask}$, benchmark notional $V^B_{ask}$, and simple returns $r^P_{ask}$, $r^B_{ask}$. Values are nonnegative; every account has a positive total on both sides. Returns and weights are decimal values.

The source checkout includes a fully synthetic three-account fixture in `data/multi_account/positions.csv`, generated by `python scripts/generate_multi_account_data.py`. The interactive tutorial is available in [English](../../tutorials/en/multi_account_attribution.ipynb) and [中文](../../tutorials/zh/multi_account_attribution.ipynb); both read this file and compare all three methods on the **same** input.

```python
import polars as pl
from brinsons import (
    macro_micro_attribution, value_weighted_total_attribution,
    hierarchical_decision_attribution,
)

positions = pl.read_csv("data/multi_account/positions.csv")
macro_micro = macro_micro_attribution(positions)
pooled = value_weighted_total_attribution(positions)
decision = hierarchical_decision_attribution(positions)
```

Each function accepts `column_period`, `column_account`, `column_sector`, `column_security`, `column_portfolio_value`, `column_benchmark_value`, `column_portfolio_return`, and `column_benchmark_return` with the displayed input names as defaults. The input frame is not renamed. The Macro→Micro and hierarchical results carry `MultiAccountColumns` with these selected roles; the pooled standard `AttributionResult` carries its calculated `ColumnNames`. `column_micro_segment` and `column_segment` select the inner grouping of the first and second methods respectively; both default to the sector field. Use the security field for a stock-level Brinson view.

## 1. Macro account attribution, then Micro Brinson

`macro_micro_attribution` first aggregates each account $a$. Let $V^P_a=\sum_{s,k}V^P_{ask}$ and $V^B_a=\sum_{s,k}V^B_{ask}$. Its whole-portfolio account weights and conditional returns are

$$
W^P_a=\frac{V^P_a}{\sum_jV^P_j},\quad
W^B_a=\frac{V^B_a}{\sum_jV^B_j},\quad
R^P_a=\frac{\sum_{s,k}V^P_{ask}r^P_{ask}}{V^P_a},\quad
R^B_a=\frac{\sum_{s,k}V^B_{ask}r^B_{ask}}{V^B_a}.
$$

The first stage applies the selected `macro_attribution` (default `fachler`) to accounts. With three effects, BF gives

$$
\begin{aligned}
A^{\rm macro}_a&=(W^P_a-W^B_a)(R^B_a-R_B),\\
S^{\rm macro}_a&=W^B_a(R^P_a-R^B_a),\\
I^{\rm macro}_a&=(W^P_a-W^B_a)(R^P_a-R^B_a).
\end{aligned}
$$

The second stage aggregates securities by `column_micro_segment` **inside each account**, forms conditional account weights $u^P_{ai}=V^P_{ai}/V^P_a$ and $u^B_{ai}=V^B_{ai}/V^B_a$, then calls the selected `micro_attribution` (default `fachler`). It requires positive portfolio and benchmark notional for each account/inner segment. For BF, the within-account effects $A^{\rm micro}_{ai},S^{\rm micro}_{ai},I^{\rm micro}_{ai}$ sum to $R^P_a-R^B_a$.

Macro selection plus interaction already represents $W^P_a(R^P_a-R^B_a)$. The integrated table **replaces** those two account effects with portfolio-account-weighted micro effects:

$$
\begin{aligned}
S^{\rm macro}_a+I^{\rm macro}_a
&=W^P_a(R^P_a-R^B_a),\\
E=R_P-R_B
&=\sum_a A^{\rm macro}_a+
  \sum_{a,i}W^P_a\bigl(A^{\rm micro}_{ai}+S^{\rm micro}_{ai}+I^{\rm micro}_{ai}\bigr).
\end{aligned}
$$

Adding the raw macro selection/interaction **again** to the integrated result would double count. `MacroMicroAttribution` exposes `macro` (the original account Brinson result), `micro_detail`, `micro_summary`, `integrated_detail`, and `integrated_summary`. Choose `macro_effects` and `micro_effects` independently as 2 or 3. The BHB/BF methods are separate callables; pass `macro_attribution=bhb` or `micro_attribution=bhb` when needed.

## 2. Pool values into one total portfolio

`value_weighted_total_attribution` aggregates a chosen global segment $i$ **across accounts**:

$$
w^P_i=\frac{\sum_a V^P_{ai}}{\sum_{a,j}V^P_{aj}},\quad
w^B_i=\frac{\sum_a V^B_{ai}}{\sum_{a,j}V^B_{aj}},\quad
r^P_i=\frac{\sum_aV^P_{ai}r^P_{ai}}{\sum_aV^P_{ai}},\quad
r^B_i=\frac{\sum_aV^B_{ai}r^B_{ai}}{\sum_aV^B_{ai}}.
$$

It then calls the selected standard `attribution` (default `fachler`, `effects=3`) once. Its benchmark is the **value-weighted mixture of the supplied account benchmark notionals**. The pooled Brinson summary matches the total portfolio/benchmark returns, but account allocation is not separately visible. Every global segment needs positive value on both sides. Account transfers and changes in beginning weights can change the interpretation across periods.

## 3. Hierarchical decision attribution

`hierarchical_decision_attribution` fixes a decision order: benchmark $\to$ portfolio account weights $\to$ portfolio sector weights within account $\to$ portfolio security weights within sector $\to$ portfolio security returns. Define normalized conditional portfolio weights $P_a,P_{s|a},P_{k|as}$ and benchmark weights $B_a,B_{s|a},B_{k|as}$ from the respective values. The five successive notional returns are

$$
\begin{aligned}
N_0&=\sum_{a,s,k} B_aB_{s|a}B_{k|as}r^B_{ask}=R_B,\\
N_1&=\sum_{a,s,k} P_aB_{s|a}B_{k|as}r^B_{ask},\\
N_2&=\sum_{a,s,k} P_aP_{s|a}B_{k|as}r^B_{ask},\\
N_3&=\sum_{a,s,k} P_aP_{s|a}P_{k|as}r^B_{ask},\\
N_4&=\sum_{a,s,k} P_aP_{s|a}P_{k|as}r^P_{ask}=R_P.
\end{aligned}
$$

Let $r^B_a=\sum_{s,k}B_{s|a}B_{k|as}r^B_{ask}$ and $r^B_{as}=\sum_kB_{k|as}r^B_{ask}$. The **BF-centered** row effects are

$$
\begin{aligned}
A^{\rm acct}_a&=(P_a-B_a)(r^B_a-R_B),\\
A^{\rm sector}_{as}&=P_a(P_{s|a}-B_{s|a})(r^B_{as}-r^B_a),\\
A^{\rm stock}_{ask}&=P_aP_{s|a}(P_{k|as}-B_{k|as})(r^B_{ask}-r^B_{as}),\\
S^{\rm stock}_{ask}&=P_aP_{s|a}P_{k|as}(r^P_{ask}-r^B_{ask}).
\end{aligned}
$$

Each stage sum equals its corresponding $N_j-N_{j-1}$; hence all four stages sum to $R_P-R_B$. The returned `detail` identifies the decision stage and its account/sector/security, `notionals` lists $N_0$ through $N_4$ per period, and `summary` contains four stage totals and exact excess. This is a **specified decision order**, not a claim that the same effects would emerge under another order. Every account/sector needs positive value on both sides; security rows can carry zero weight if their returns are explicitly provided.

## Multiple periods

The three calculations produce **per-period** results when given several periods. For a full-horizon **arithmetic** attribution, select a named linker at its own function entrance:

```python
from brinsons import (
    link_carino, link_macro_micro_attribution,
    link_hierarchical_decision_attribution,
)

macro_horizon = link_macro_micro_attribution(macro_micro, linking=link_carino)
decision_horizon = link_hierarchical_decision_attribution(decision, linking=link_carino)
pooled_horizon = link_carino(pooled)
```

The first two linking helpers apply the selected period factor to **every** additive account/decision channel and report `linking_method`. They accept arithmetic factor linkers—Cariño, GRAP, Frongello, and Menchero. Geometric linking has a different multiplicative target and is intentionally rejected for these additive stage tables. The pooled `AttributionResult` can be passed directly to any existing linker; geometric results must be interpreted with the [geometric identity](linking.md).

The sample assumes no intra-period transfers, flows, fees, or changing notional definitions. As [CFA Institute's portfolio evaluation overview](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/portfolio-performance-evaluation) explains, macro attribution concerns sponsor-level decisions while micro attribution concerns manager-level decisions; a credible analysis must follow the actual decision process and reconcile to the measured total.
